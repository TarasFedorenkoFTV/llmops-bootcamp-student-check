# Резюме

Курс пройдено повністю: 12 уроків, 12 лабораторних, 6 домашніх завдань, фінальний прогін
з чистого клону і eval-гейт, перевірений на справжніх GitHub Actions.

**Що зроблено фактично**

| Артефакт | Стан |
|---|---|
| Робочий репозиторій | `TarasFedorenkoFTV/llmops-bootcamp-student-check` |
| Журнал проходження | `student-journal.md`, 1300+ рядків, писався після кожного кроку |
| Прогони eval-гейта | 4 у GitHub Actions: `capstone` failure → success, `demo/broken-prompt` failure → success |
| Захист гілки | `main` protected, `eval` = required status check, `enforce_admins: true` |
| Датасет | 6 стартових + 7 власних кейсів = 13, поріг 12 |
| Консоль | усі 6 плиток і всі 3 картки живі |

**Головний висновок.** Курс вчить рівно тому, що обіцяє, і вчить добре. Ламається він не на
змісті, а на **стиках**: між уроком і лабою, між лабою і ДЗ, між ДЗ і чек-лістом тижня,
між порадою про порти і CI-шаблоном. Вісім із десяти найгостріших дефектів — це не помилка
в тексті, а два документи одного репозиторію, які не знають один про одного.

**Оцінки:** ясність викладу **5** · повнота теми **4** · прикладність **5** ·
рівномірність навантаження **2** · чи заплатив би власні гроші **4**.

# 1. Що я тепер умію, чого не умів

## Тиждень 1 — основа і промпти

Можу відкотити промпт однією операцією (`POST /prompts/v2/activate`) і побачити в лозі,
яка версія обслуговувала конкретний запит:

```sql
SELECT created_at::time(0), model, prompt_version, status
FROM requests ORDER BY created_at DESC LIMIT 5;
```

До курсу промпт у мене був рядком у коді, і на питання «яка версія відповідала користувачу
вчора в 19:40» я не мав відповіді в принципі.

## Тиждень 2 — маршрутизація і вартість

Можу назвати вартість **конкретного** запиту в момент відповіді і показати важіль економії:

```
    model    | pt | ct | cost_usd
 mock-strong | 21 |  9 | 0.000142     <- ескалація
 mock-mini   | 17 | 22 | 0.000016     <- FAQ          різниця 9x
```

Умію розслідувати сплеск вартості трьома зрізами: по днях (коли почалося) → по моделях
(чи не поїхав роутер) → по `prompt_version` із середніми `prompt_tokens` (чи не подовшав промпт).

## Тиждень 3 — кеш і інструменти

Складаю ключ кешу так, що rollback промпта автоматично інвалідує записи — і **довів** це,
а не повірив:

```
до rollback:        [ 0ms] Щоб скинути пароль: відкрийте сторінку входу…
-> activate v1
після rollback:     [12ms] не знаю          <- кеш не віддав старе, пішов новий виклик
-> activate v2
після promote:      [ 0ms] Щоб скинути пароль…   <- старий ключ живий, миттєве відновлення
```

Обкладаю tool-виклик таймаутом 3 с проти ~10 с загального бюджету відповіді (ліміт
інструмента мусить бути помітно меншим за загальний) і ключем ідемпотентності.

## Тиждень 4 — надійність і безпека

Влаштовую керований інцидент і показую, що збій коштує **51–68 мс**, а не 8 секунд
прихованих ретраїв. Відтворив самостріл circuit breaker'а і одужання через half-open:

```
1) 3 збої поспіль -> open
     fail 1: [ 55ms]   fail 2: [ 53ms]   fail 3: [  0ms]
2) ЗДОРОВЕ питання одразу після:
     t+0s:   [  0ms] Вибачте, тимчасові проблеми…   <- САМОСТРІЛ: провайдер живий, breaker відкритий
3) через 6с half-open пропускає пробний запит:
     t+6s:   [ 12ms] Можу допомогти зі входом, замовленнями та поверненнями…
```

Провів незворотну дію через чергу так, що **5 одночасних approve дають один тікет**
(атомарний claim через `TryUpdate` перед виконанням).

## Тиждень 5 — спостережуваність і evals

Бачу інцидент, якого не бачить `/health`:

```
/health:        {"status":"ok"}                        <- "усе зелене"
/observability: {"error_rate_pct":15.6,"fallback_events":4,"requests":32,"p95_ms":98}
/providers:     mock-mini · down (fails=3) · mock-strong · ok
```

Рахую p95 одним `percentile_cont` і звіряю вітрину з джерелом після кожної зміни агрегатів.

## Тиждень 6 — CI-гейт

Блокую merge регресії **фізично**, а не за домовленістю:

```
eval: 8/13 passed, threshold 12
##[error]Process completed with exit code 1

$ gh pr merge 3 --merge
X Pull request #3 is not mergeable: the base branch policy prohibits the merge.
```

Написав runbook на чотири класи інцидентів у форматі
«симптом → підтвердити → дія → переконатися» і rollback-критерії **до** викочування.

> **Головне, чого не було.** Я більше не думаю про LLM-фічу як про виклик API. Думаю як про
> контур із вісьмома точками рішення, кожна з яких лишає слід у лозі.

# 2. Де курс мене втратив би

Я маю 6+ років бекенду і знаю Docker. Нижче — місця, де реальний студент із роботою
і сім'єю припинив би курс.

## 2.1. Урок 1, лаба крок 1–2 — найгірше місце курсу

У мене на хості зайняті `8080` (EDB PEM Apache) і `5432` (PostgreSQL 18). Troubleshooting
обіцяє симптом `port is already allocated` — **його не було**. Docker на Windows підняв стек
«успішно», і на порту 8080 виявилося два слухачі:

```
TCP    0.0.0.0:8080   LISTENING   13528   <- docker-proxy
TCP    0.0.0.0:8080   LISTENING   4812    <- Apache
```

Далі — як пощастить із резолвом:

```
localhost:8080  -> {"status":"ok"}                 (через [::1] у docker)
127.0.0.1:8080  -> <title>404 Not Found</title>    (IPv4 -> Apache)
```

Студент бачить «усе працює» і йде далі — а потім Troubleshooting того ж гайду радить йому
`127.0.0.1` як фікс проксі-проблем і заганяє в чужий Apache. Далі виявляється, що
`docker-compose.override.yml` із `ports: [...]` **не допомагає**: Compose зливає list-поля,
і треба `!override`. Це знання не з курсу. Це вечір, і тут закінчують курс.

## 2.2. Гайд §6 — команда прогону evals не працює в Git Bash

Це команда, на якій стоять тижні 5–6 і CI.

```
# як у гайді, без префікса:
python: can't open file '//E:/run.py': [Errno 2] No such file or directory

# з фіксом із того самого абзацу (MSYS_NO_PATHCONV=1):
python: can't open file '/e/run.py': [Errno 2] No such file or directory
```

Другий варіант ламається тому, що `MSYS_NO_PATHCONV=1` вимкнув конверсію **і для `$(pwd)`**,
тож джерело монтування стало літеральним `/c/Work/...`, якого Docker Desktop не знає.
Робочий варіант у матеріалах відсутній:

```bash
MSYS_NO_PATHCONV=1 docker run --rm --network <project>_default \
  -e SERVICE_URL=http://service:8080 -e PYTHONUTF8=1 \
  -v "C:/Work/llmops-student/evals:/e:ro" python:3.12-slim \
  python /e/run.py --dataset /e/golden.jsonl --threshold 12
```

Додатково: діагноз у гайді неточний. Там сказано, що MSYS псує шлях **у монтуванні**;
насправді зламався **аргумент команди**.

# 3. Дефекти матеріалів

## 3.1. Блокує проходження

### Д-01 · Команда прогону evals не працює на Windows

- **Де:** `GETTING_STARTED.md`, §6
- **Що не так:** команда не працює в Git Bash; діагноз неточний (ламається аргумент
  команди, а не монтування); запропонований фікс `MSYS_NO_PATHCONV=1` ламає `$(pwd)` у `-v`.
  Альтернатива з хоста недоступна, якщо порт 8080 зайнятий — тобто **жодного робочого
  способу за матеріалами** не лишається.
- **Як має бути:** дати робочий рецепт (`MSYS_NO_PATHCONV=1` + Windows-шлях джерела)
  або обгортку-скрипт `evals/run.sh`.

### Д-02 · Точка входу не веде нікуди

- **Де:** `docs/longreads/index.html`
- **Що не так:** 12 карток уроків — це `<div class="card">`, не посилання. У всьому файлі
  рівно два `href`, обидва на GitHub. Пре-реквізити, гайд і ДЗ описані як «документ, що
  видається разом із курсом» — без шляхів, хоч лежать у тому ж репозиторії.
- **Як має бути:** картки → `<a href="L01.html">`; у таблиці «Все для старту» — реальні
  шляхи `starter/PREREQUISITES.md`, `starter/GETTING_STARTED.md`, `starter/homework/`.

### Д-03 · Порада про порти несумісна з CI-шаблоном курсу

- **Де:** `GETTING_STARTED.md` §8 ↔ `.github/workflows/eval-gate.yml`
- **Що не так:** §8 радить «перемап порт у `docker-compose.yml`». `docker-compose.override.yml`
  комітиться і підхоплюється Compose автоматично, тому в CI сервіс теж їде на нестандартний
  порт — а крок `Wait for service` захардкоджено чекає `http://localhost:8080/health`.
  Я впав на цьому в реальному Actions: 3 хв 20 с таймауту, при тому що в логах сервіс
  пише `Now listening on: http://0.0.0.0:8080`. Симптом максимально неінформативний.
- **Як має бути:** попередити в §8 і додати `docker-compose.override.yml` у `.gitignore`
  стартера; або в workflow не бити в хостовий порт (evals можуть ходити всередині
  docker-мережі, як радить §6 того самого гайду).

### Д-04 · Лаба L08 крок 4 недосяжна на наданому mock

- **Де:** урок 8, лаба крок 4 + блок 09 ↔ `mock-provider/Program.cs:80`
- **Що не так:** лаба вимагає додати red-team кейси, блок 09 радить «по одному кейсу на
  родину». Детект mock — дві англійські підстрічки, тому 3 з 4 родин проходять наскрізь.
  Результат — червоний прогін при вимозі hw4 «evals зелені». Детекту injection у сервісі
  не просить ні обов'язкова, ні опційна частина hw4.
- **Як має бути:** або детект injection стає пунктом hw4, або mock ловить три родини,
  або лаба явно каже «спершу реалізуй вхідний guardrail — блок 04».

### Д-05 · У `starter/` немає `.gitignore` — ключ провайдера летить у публічний репозиторій

- **Де:** `starter/` (у корені курсу `.gitignore` є)
- **Що не так:** крок 0 копіює тільки `starter/`, тому репозиторій студента живе без ігнорів.
  При цьому §1 пропонує білдити `service`/`ui` локально, а §10 — створити `gateway/.env`
  з `OPENAI_API_KEY`. Перше дає `bin/obj/node_modules` у PR, друге — **секрет у публічному
  репозиторії**.
- **Як має бути:** додати `.gitignore` у `starter/`.

### Д-06 · hw5 п.4 суперечить уроку 8

- **Де:** `hw5.md` п.4 ↔ L08 блок 02
- **Що не так:** «прогін із `__fail_503` у кожному `input` має дати **0 пройдених**;
  будь-який зелений кейс — на доопрацювання». Фактично:

```
faq-1: FAIL   faq-2: FAIL   order-1: FAIL   refund-1: FAIL   caps-1: FAIL
thanks-1: FAIL   escalate-1: FAIL   hitl-1: FAIL   pii-1: FAIL
safety-1: ok   safety-2: ok   safety-3: ok   safety-4: ok
eval: 4/13 passed
```

  Чотири зелені — і жоден не дефект: це `expect_refusal`-кейси, і вони зеленіють тому, що
  guardrail стоїть **на межі, до виклику моделі**, як велить L08 блок 02. Відмовити на
  injection під час падіння провайдера строго правильніше, ніж відповісти «тимчасові
  проблеми». Лікування, яке пропонує hw5 (`forbid` із фрагментом заглушки), не застосовне —
  у відповіді немає тексту заглушки.
- **Як має бути:** виняток для `expect_refusal`-кейсів, які обслуговує guardrail; критерій
  формулювати як «жоден `expect`-кейс не зеленіє».

## 3.3. Знахідка, якій немає місця в матеріалах

### Д-26 · Cache-hit маскує відновлення після інциденту

- **Де:** стик L05 (кеш) × L07 (circuit breaker) × L09 (плитка провайдерів) — жоден урок
  не зводить їх разом
- **Що не так:** перевірка «чи відпустило» питанням із кешу не заходить у gateway, тому
  breaker не отримує пробного запиту в half-open і не закривається. Плитка «Надійність
  провайдерів» показує `down` **скільки завгодно довго**, поки трафік іде з кешу:

```
провайдери після "відновлення" питанням З КЕШУ:   mock-mini · down (fails=3)
питання з УНІКАЛЬНИМ текстом (реальний виклик):   [11ms] нормальна відповідь
провайдери після нього:                            mock-mini · ok (fails=0)
```

  L09 блок 05 наполягає: «плитка не має права зеленіти посеред інциденту». Зворотний
  випадок — плитка не має права червоніти **після** інциденту — не розглянутий. При цьому
  hw6 п.3 прямо вимагає показати «сплеск і **спад** fallback», тобто рівно те, що цей
  дефект ламає.
- **Як має бути:** згадати стик; правильний фікс — фоновий health-probe провайдера повз кеш,
  а не перевірка живим трафіком.

# 4. Чи виконуване ДЗ з матеріалів уроку

## hw1 — логування + prompt registry · **ТАК**

Уроків досить. SQL у блоці 06, атомарний `UPDATE prompts SET active = (version = @v)`
у блоці 07, «як відкривати з'єднання — подивись на сусідній `LogRequest`» — і цього справді
достатньо. Зробив з першого заходу, ~60 рядків C# з нуля. Зовнішніх джерел — нуль.

## hw2 — routing + cost · **ТАК, ІЗ ЗАПАСОМ**

Урок дає `Route()`, словник прайсу, формулу `costUsd` і скелет `/cost` **готовими до
копіювання**. Це не «виконуване», це «переписуване». Витратив утричі менше часу, ніж на hw1 —
при тому що L01 обіцяв «складне починається з тижня 2».

## hw3 — кеш + інструменти · **ТАК для обов'язкового, НІ для лаби**

Кеш і `RunTool` — прямо з уроку. Але лаба L06 крок 3 вимагає таймаут та ідемпотентність,
а урок дає `static string? RunTool(name) => switch` — функцію **без стану**, тоді як
ідемпотентність без стану неможлива за визначенням. Довелося виносити в `static class`
через C#-правило, якого §9a не дає. Плюс спосіб перевірки з hw3 не працює: `__delay`
затримує mock, тобто виклик моделі, а не інструмент — перевірено, `real 0m2.086s`,
гілка таймауту не торкнулася.

## hw4 — надійність + безпека · **Обов'язкове ТАК, лаба L08 крок 4 НІ**

Fallback і HITL повністю з уроків. Але red-team кейси без детекту injection у сервісі дають
червоний прогін, а детекту не просить ні обов'язкова, ні опційна частина. Довелося писати
з нуля: три родини патернів плюс перевірка на false positives на чотирьох нормальних
питаннях. Це робота поза будь-яким ДЗ.

## hw5 — observability + evals · **ТАК, але критерій п.4 суперечить L08**

`/observability`, `/providers` і датасет — з уроку. А п.4 неможливо виконати, якщо guardrail
стоїть на межі, як велить L08. Обидва шляхи провалюють одне з двох ДЗ (див. Д-06).

## hw6 — CI-гейт + інцидент · **ТАК — і тільки на реальному CI**

Шаблон workflow готовий, поріг рахується за правилом. Але L11 блок 04 має рацію буквально:
я прогнав кроки локально, отримав `exit 1 → exit 0`, був упевнений — і впав на справжньому
Actions через `docker-compose.override.yml`, якого локально не існує як проблеми.
**Без GitHub тиждень 6 дає ілюзію готовності.**

## Зовнішні джерела

Знадобилися **тричі**, і всі три — не про LLMOps:

1. `!override` у Compose (list-поля зливаються, а не замінюються);
2. `MSYS_NO_PATHCONV` + Windows-шляхи в `docker run`;
3. правила top-level statements у C# (`CS0106`, `CS8803`).

Тобто по темі курсу матеріалів достатньо; спотикаєшся на оточенні.

# 5. Чого мені забракло як інженеру

**Калібрування grader'а на живій моделі.** Курс це чесно визнає врізкою «Чесно про межу
нашого контуру»: на mock кейси падають детерміновано, а робота з флейками — «якої тут немає».
Я виходжу з датасетом на 13 кейсів і нульовим уявленням, чи він виживе на реальній моделі
бодай день. Найбільша дірка, і вона за побудовою безкоштовного курсу.

**Ідемпотентність у бойовій формі.** Курс дав ключ, який не працює для сценарію, яким його
мотивують. Першого дня в реальній задачі я зроблю `request_id` і отримаю подвійні тікети.

**Одне звернення ≠ один виклик.** Порада правильна, схема її забороняє. Коли додам
логування кожної спроби fallback — переробляти облік.

**Multi-turn і стрімінг.** L09 перелічує, що зміниться (три латентні метрики, помилка
посеред 200, кеш тільки зібраної відповіді) — і не робить. Перше, що попросять продуктові,
це стрімінг.

**Черга approvals у базі.** L12 сам каже: це робиться відразу, без сигналу. Я маю
`ConcurrentDictionary`, і мій runbook містить пункт «не рестартуй з непорожньою чергою» —
тобто я забалансував дефект дисципліною.

**Мультитенантність у ключі кешу.** L05 називає це «гарантованою аварією» і найдорожчим
випуском із ключа — і не дає жодної практики: тенанта в контурі курсу немає.

**Реальні гроші.** Усі мої цифри — `$0.0002`. Я не бачив, як виглядає рахунок, який змушує
ухвалювати рішення.

**Ясність викладу — 5.** Найкраще, що я читав у цьому жанрі. Кожен блок починається
з проблеми, кожен принцип перевірюваний, «типові помилки» — з власного досвіду автора,
включно з історією про самостріл із breaker'ом без half-open і про два червоні прогони
в Actions при підготовці курсу. Врізки «чесно про межу нашого контуру» я б зробив
стандартом індустрії.

**Повнота теми — 4.** Шар «між застосунком і моделлю» закритий сумлінно, а межі названі
прямо (не RAG, не файнтюн, не фронтенд). Мінус один — за те, що найважча частина evals
(калібрування на живій моделі) відсутня за побудовою, а мультитенантність і multi-turn
згадані як «гарантована аварія» без жодної практики.

**Прикладність — 5.** Усе, що я написав, працює в системі, яку можна підняти однією
командою й показати. Runbook, 30-day rollout і KPI-таблиця — три артефакти, які я
в понеділок принесу на роботу без переробки. Таблиця з L12 блоку 08 («який шар додавати
наступним і за яким сигналом», з колонкою «чого НЕ робити раніше») — найцінніша сторінка курсу.

**Рівномірність навантаження — 2.** Найслабше місце. L01 обіцяє «складне починається
з тижня 2» — а hw2 виявився найлегшим ДЗ курсу (весь код в уроці готовий), тоді як hw1
вимагав писати з нуля. Тиждень 4 — вісім механізмів за один PR плюс робота, якої не просить
жодне ДЗ. Тиждень 6 — найдешевший за кодом і найдорожчий за налагодженням оточення.
Обіцянка «~5–7 годин на тиждень» тримається лише якщо порти вільні.

**Чи заплатив би власні гроші — 4.** Так — за уроки 2, 5, 7, 8, 9 і за таблицю
з L12 блоку 08. Це рівно ті знання, за якими я прийшов, і вони не гуглівські: не «як
покликати модель», а «як не втратити контроль над нею». Не 5 — через вхідний бар'єр:
перший вечір з'їдають порти й `docker run` під Windows, і на цьому відсіється частина
людей, які саме цей контент і мали отримати. Полагодьте Д-01, Д-02, Д-05 — і це впевнена п'ятірка.
