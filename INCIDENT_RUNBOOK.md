# Incident runbook — SupportGW

Формат: **симптом → підтвердити → дія → переконатися**. Читач — я сам під адреналіном,
тому команди повні, назви плиток точні.

> **Порти цього прогону:** service `localhost:28080`, postgres `25432` (на хості зайняті
> 8080/5432 і 18080/15432). У «канонічному» стеку курсу — 8080/5432.

---

## 1. Провайдер лежить

| Такт | Що саме |
|---|---|
| **Симптом** | скарги «бот вибачається»; у чаті «Вибачте, тимчасові проблеми на нашому боці» |
| **Підтвердити** | `curl -s localhost:28080/observability` → `error_rate_pct`↑, `fallback_events`↑; `curl -s localhost:28080/providers` → `down`/`degraded`; у лозі 503/429 |
| **Дія** | **руками нічого:** fallback і graceful degradation працюють, circuit breaker прибирає очікування таймаутів. Стежити за `fallback_events` |
| **Переконатися** | `/providers` → `ok`; `fallback_events` перестав рости |

> **Пастка (перевірено на цьому прогоні):** «переконатися» питанням, яке вже в кеші,
> **не працює** — cache-hit не заходить у gateway, breaker не отримує проби, `/providers`
> лишається `down`. Перевіряй **унікальним** текстом:
> ```bash
> curl -s -X POST localhost:28080/chat -H "Content-Type: application/json" -d '{"message":"probe unique-2026"}'
> curl -s localhost:28080/providers
> ```

## 2. Якість просіла

| Такт | Що саме |
|---|---|
| **Симптом** | «бот верзе дурниці» при зелених HTTP-метриках |
| **Підтвердити** | `prompt_version` у свіжих рядках — чи збігається сплеск скарг з активацією; локальний прогін evals — червоний? |
| **Дія** | rollback: `POST /prompts/{стара}/activate` — секунди, без деплою. Кеш чиститься сам (версія — частина ключа) |
| **Переконатися** | прогін evals зелений; скарги стихають |

```bash
curl -s localhost:28080/prompts
curl -s -X POST localhost:28080/prompts/v2/activate
```

## 3. Черга approvals протухла

| Такт | Що саме |
|---|---|
| **Симптом** | користувач написав «поверніть гроші» і чекає |
| **Підтвердити** | `curl -s localhost:28080/approvals` → `waiting_sec` великий |
| **Дія** | оператор: `approve` або `reject` (обидва — рішення, обидва лічаться) |
| **Переконатися** | `pending` порожній або `waiting_sec` малий |

> **Відомий компроміс (L08):** черга в пам'яті процесу — рестарт губить незакриті
> заявки. Перед `up --build -d service` перевіряй `/approvals`, не рестартуй з
> непорожньою чергою. Доросла форма — таблиця в базі.

## Rollback-критерії (записані ДО викочування, L11 блок 09)

```
Відкочуємо, якщо:
  eval pass rate < 9/10               (прогін після деплою)
  або fallback_events зростає         протягом 15 хв
  або error_rate_pct > 5%             протягом 15 хв
Хто смикає: черговий, без погоджень.
Як (промпт): POST /prompts/{попередня}/activate   — секунди
Як (код):    revert PR + merge (гейт перевірить)  — хвилини
```

## Постмортем: два питання

1. **Що зробимо, щоб не повторилося?** — механізм або кейс у `golden.jsonl`, не «будемо уважнішими».
2. **Як ми дізналися?** — якщо «зі скарг», у спостережуваності діра: інцидент має спершу
   з'явитися на консолі. Розбираємо механізми, а не людей.
