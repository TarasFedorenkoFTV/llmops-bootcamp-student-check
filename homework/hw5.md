# HW5 (після L09–L10): observability + evals

Мета тижня: система видна наскрізь (не тільки uptime), а якість перевіряється
повторюваним прогоном, а не оком.

> **Навіщо це в реальній системі.** Дві дрібниці вирішують, чи буде що дивитися
> під час інциденту. Перша: ключові переходи стану мусять логуватися на рівні,
> увімкненому в проді — нам довелося окремим рішенням підняти лайфсайкл-логи з
> debug до info, бо найцінніші події існували в коді й не існували в реальності.
> Друга: плитка не має права зеленіти посеред інциденту — статус провайдера,
> прибитий цвяхом до «ok», бреше саме тоді, коли ви на нього дивитесь.

## Обов'язково

1. Реалізує `GET /observability`: requests за сьогодні, p95 latency, error rate — з
   таблиці `requests`; cache-hit % і fallback-лічильник — зі свого коду (HW3/HW4).
2. Реалізує `GET /providers` — статус провайдерів для консолі.
3. Розширює golden dataset: мінімум 4 власні кейси (позитивні й негативні) у
   `evals/golden.jsonl`; за потреби — власний grader у `evals/run.py`.

## Опційно (не оцінюється)

- Таксономія помилок: окремі лічильники за причинами (429 провайдера, timeout
  інструмента, відмова guardrail).
- Model-based grader (LLM-as-judge) — потребує реального ключа; його виклики теж
  порахувати у вартість.

## Що здає

PR, де всі плитки консолі живі (числа, не «—»), і evals проходять з розширеним датасетом.

## Що перевіряє ментор

| Перевірка | Як | Очікується |
|---|---|---|
| Плитки живі | кілька запитів (включно з повтором і `__fail_503`), потім консоль | усі 6 плиток з числами; cache-hit > 0; fallback > 0 |
| Дані чесні | звірити requests-плитку з `SELECT count(*) FROM requests WHERE created_at::date = CURRENT_DATE` | збігається |
| Провайдери | `GET /providers` + картка в консолі | статус віддається, картка не «—» |
| Власні кейси | `git diff` по `evals/golden.jsonl` | ≥4 нові кейси, серед них негативні, **жодного видаленого** зі стартових |
| Evals | прогін із розширеним датасетом | зелені; поріг за правилом: N−1 з N при N≤10, далі ≥85%; значення й причина — у README |

## Самоперевірка перед здачею

Зроби кілька запитів (включно з повтором і `__fail_503`) — плитки показують
requests, cache-hit > 0, fallback > 0. Якщо якась плитка «—» — її ендпоінт ще
віддає заглушку.
