## Спільні правила здачі

- ДЗ живе у **твоєму** репозиторії (клон стартера — GETTING_STARTED, §11 крок 0) і після курсу залишається тобі як портфельний проєкт.
- Здача = гілка + Pull Request у власному репо. CI на PR ганяє evals і червоніє на регресії. Здача — це не лише код: описи рішень у PR (hw3) і README-розділи (hw6) — такі самі артефакти перевірки.
- Репозиторій — публічний, або приватний із ментором у колабораторах. Посилання на PR кидаєш у канал потоку курсу; перевірка — до наступного заняття.
- Кожне наступне ДЗ гілкуй від `main` **після мержа попереднього** — інакше в diff буде минулий тиждень і перевірка сповільниться.
- Evals ганяються командою з GETTING_STARTED §6; до уроку 10 використовуй runner як чорну скриньку.
- Для ментора: процес перевірки, критерії прийому/повернення і шпаргалка верифікації — [docs/MENTOR_GUIDE.md](../../docs/MENTOR_GUIDE.md).
- Застряг? Еталонні рішення — репозиторій `llmops-bootcamp-solutions`, бранчі `w1`…`w6` (тиждень = бранч). Політика проста: спершу власна спроба, потім звірка — еталон учить лише після того, як ти сам(-а) вперся(-лась).
- В описі PR — що зробив і скрін консолі.
- Місця в коді підписані `TODO(student, W#)` у `service/Program.cs`.
- Все робиться на mock, без реального ключа.
- Орієнтир по часу: 2–3 години після guided lab. Виходить суттєво більше — неси
  питання на Q&A, не закопуйся.
- Критерії перевірки в кожному ДЗ відкриті — ментор дивитиметься саме на них.
